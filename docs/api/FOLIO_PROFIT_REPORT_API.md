# Отчёт прибыли Киев / Одесса из ФОЛИО

## Назначение

Read-only endpoint строит месячный отчёт прибыли по данным `Paint_Ua` и возвращает контрольный реестр расходов. Он не изменяет документы, остатки или схему ФОЛИО.

Endpoint предназначен только для внутреннего `/admin`-контура. В самом модуле нет отдельной финансовой авторизации: до публикации наружу доступ должен быть закрыт существующей VPN/proxy-аутентификацией.

## Запросы

Итог без полного реестра документов:

```http
GET /admin/folio/profit-report?month=2026-07
```

Итог с документами, на которых построен расчёт:

```http
GET /admin/folio/profit-report/audit?month=2026-07
```

Параметры:

| Параметр | Обязательный | Значение |
|---|---:|---|
| `month` | да | Месяц `YYYY-MM` |
| `odesaTaxShare` | нет | Доля общего налогового пула для Одессы, от 0 до 1; по умолчанию `3/7 = 0.4285714286` |
| `rubToUahRate` | нет | Курс RUB→UAH; по умолчанию `0.41` |
| `odesaMasterClassIncome` | устарел | Игнорируется. Оставлен временно только для совместимости со старым фронтом |
| `odesaMasterClassReturn` | устарел | Игнорируется. Оставлен временно только для совместимости со старым фронтом |
| `odesaAdditionalSalary` | нет | Дополнительная зарплата Одессы. Если параметр отсутствует, backend применяет `5000.00`; явный `0` отключает добавление для выбранного месяца |
| `kyivStockWarehouseIds` | нет | Склады для остатков Киева; по умолчанию `1,7,12` |
| `odesaStockWarehouseIds` | нет | Склады для остатков Одессы; по умолчанию `5` |

Пример с явным отключением дополнительной зарплаты для выбранного месяца:

```http
GET /admin/folio/profit-report/audit?month=2026-07&odesaAdditionalSalary=0&kyivStockWarehouseIds=1,7,12&odesaStockWarehouseIds=5
```

Параметры МК больше не являются ручными. Если старый клиент всё ещё передаёт их,
backend не применяет значения и возвращает предупреждение
`MASTER_CLASS_LEGACY_PARAMETERS_IGNORED`. В `inputs` поля
`odesaMasterClassIncome` и `odesaMasterClassReturn` всегда равны `null`, поэтому
старый фронт не должен использовать их для заполнения формы следующего месяца.

`inputs.odesaAdditionalSalary` содержит фактически применённую сумму, а
`inputs.odesaAdditionalSalarySource` — `DEFAULT` или `REQUEST_OVERRIDE`.

Складские списки можно передавать через запятую либо повторяющимися query-параметрами. Пустой список запрещён. Номера проверяются по `SCLAD_R`, дубли удаляются, а один склад нельзя одновременно отнести к двум городам. Список для выбора фронт получает через `GET /ref/warehouses`.

## Правила расчёта

### Валовая прибыль

- источник: расходные накладные `SCL_NAKL` + строки `SCL_MOVE`;
- формула: `SUM_PREDM - SUM_UCHET`;
- Киев: склады `1, 7, 12`;
- Одесса: склад `5`;
- учитываются проведённые не-возвратные расходные накладные;
- организация типа `Я` исключается, как в старом Excel;
- доход и возврат МК Одессы определяются автоматически по правилам следующего раздела;
- если строка дохода МК уже вошла в базовую валовую прибыль, backend вычитает эту
  уже учтённую маржу из корректировки и не допускает двойного прибавления.

Для июля 2026 прямой read-only контроль базы дал `264 551,50` грн для Киева и `98 577,61` грн для Одессы до корректировки МК. Разница Киева `2,08` грн со старым Excel (`264 553,58`) оставлена как контрольное предупреждение: старые поля ФОЛИО имеют тип `FLOAT`.

### Мастер-класс Одессы

Источник — только `SCL_NAKL` + `SCL_MOVE`, склад `5`, календарный месяц по
`SCL_NAKL.DATE_P_POR` с полуинтервалом `[первый день; первый день следующего
месяца)`. Для каждого месяца выбирается строго один артикул:

| Месяц | Точный `NAME_PREDM` / `COD_ARTIC` |
|---|---|
| январь | `Мастер-Класс январь` |
| февраль | `Мастер-Класс февраль` |
| март | `Мастер-Класс март` |
| апрель | `Мастер-Класс апрель` |
| май | `Мастер-Класс май` |
| июнь | `Мастер-Класс июнь` |
| июль | `Мастер-Класс июль` |
| август | `Мастер-Класс август` |
| сентябрь | `Мастер-Класс сентябр` — именно без мягкого знака |
| октябрь | `Мастер-Класс октябрь` |
| ноябрь | `Мастер-Класс ноябрь` |
| декабрь | `Мастер-Класс декабрь` |

Строка включается в доход, когда она проведена, тип накладной и движения —
расход `Р`, а признаки возврата не установлены. Строка включается в возврат,
когда она проведена, оба типа — приход `П`, а вид операции точно равен
`ВОЗВРАТ`. Обычные приходы, непроведённые и неоднозначные строки не входят в
суммы, остаются в аудите с `classification=IGNORED` и дают предупреждение.

Сумма строки берётся из `SCL_MOVE.SUM_PREDM`. Строки дедуплицируются по
`SCL_MOVE.RECNO`. Формулы:

```text
netContribution = income - returns
grossAdjustmentApplied = netContribution - grossProfitAlreadyInBase
```

`grossProfitAlreadyInBase` — часть доходных строк МК, которая уже соответствует
общему правилу валовой прибыли (`SUM_PREDM - SUM_UCHET`). Поэтому итог Одессы не
удваивает один и тот же доход.

Если точного артикула месяца нет в `ALL_ARTC`, backend возвращает
`MASTER_CLASS_ARTICLE_NOT_FOUND`, `articleFound=false` и `complete=false`.
Ноль при существующем артикуле и отсутствии подходящих строк является корректным
нулём, а не ошибкой.

Контроль владельца за июль 2026 по предоставленным спискам ФОЛИО:

- доход: 17 строк, `10 740.00` грн;
- возвраты: 9 строк, `6 050.00` грн;
- чистый вклад: `4 690.00` грн.

Эти значения подтверждены предоставленными экранами штатного ФОЛИО; после
деплоя их нужно повторно сверить через `/audit` с конкретными документами.

### Период расхода

Если в служебном примечании есть маркер `YYYY MM`, он задаёт месяц отчёта. Иначе используется дата документа. Примечание применяется только внутри классификатора и не возвращается API, поскольку может содержать платёжные реквизиты.

### Расходы

- пустой склад в старом правиле означает «все склады»; действуют остальные признаки;
- подтверждённые коды аренды, коммунальных, зарплаты, банка, хозяйственных, рекламы, транспорта, интернета и телефона распределяются по Киеву/Одессе;
- банковские услуги: склад `5` — Одесса, остальные и пустой склад — Киев;
- `ВЫХОДЦЕВ` с признаком бухгалтерских услуг — целиком Киев;
- зарплата Донецка конвертируется из RUB в UAH (`95 800 × 0,41 = 39 278` для июля);
- общий налоговый пул `MALAFOP` делится по зарегистрированным сотрудникам: Одесса `3/7`, Киев `4/7`;
- налоговый пул `KONDFOP` относится на Киев;
- оплата поставщикам не повторяется поверх себестоимости товара;
- внутренние перемещения денег, реализация и излишки исключаются;
- импортный транспорт показывается отдельной строкой `CAPITALIZED_IN_INVENTORY`, но не вычитается повторно: он уже увеличил учётную стоимость и уменьшает валовую прибыль при продаже товара;
- неизвестные документы не влияют на прибыль, попадают в аудит и делают `complete=false`.

### Формула города

```text
grossProfit = baseGrossProfit + grossAdjustmentApplied
profit = grossProfit - operatingExpenses
```

Поле города `manualGrossAdjustments` сохранено в JSON ради совместимости, но
теперь содержит рассчитанную backend корректировку МК, а не ручной ввод.

`capitalizedCostTotal`, `excludedDocumentAmount` и `unclassifiedDocumentAmount` — контрольные суммы, а не дополнительные вычеты.

### Исторические остатки складов

Остатки возвращаются в блоке `inventory` отдельно по Киеву и Одессе. Для каждого города и склада показаны:

- учётная стоимость на начало месяца;
- учётная стоимость на конец месяца;
- изменение стоимости;
- число ненулевых товарно-складских позиций;
- число отрицательных позиций;
- число ненулевых позиций с нулевой учётной стоимостью.

Исторический остаток не берётся из текущего `SCL_ARTC.KON_KOLCH`. Он восстанавливается по подтверждённому инварианту штатного учёта ФОЛИО:

```text
quantity(asOf) = NACH_KOLCH + Σ(+П KOLC_PREDM − Р KOLC_PREDM)
accountingValue(asOf) = NACH_KOLCH × UCHET_0_C
                      + Σ(+П SUM_UCHET − Р SUM_UCHET)
```

В движение включаются строки `SCL_MOVE` с `STND_UCHET=1`, датой строго раньше следующей границы и типом `П` или `Р`. Начало месяца использует движения раньше первого дня, конец — раньше первого дня следующего месяца.

`accountingValueChange` является информационным показателем и не прибавляется к `profit`: валовая прибыль уже использует учётную себестоимость проданного товара. Отрицательные позиции или ненулевые позиции с нулевой стоимостью дают предупреждение и `complete=false`.

## Ответ и аудит

- `cities` — прибыль по городам;
- `inventory` — историческая учётная стоимость выбранных складов;
- `expenses` — агрегаты по статье, городу и способу учёта;
- `documents` — реестр исходных кассовых/банковских документов только в `/audit`;
- `masterClass` — автоматический итог МК: выбранный SKU, суммы, количество строк,
  защита от двойного учёта и состояние аудита;
- `masterClassDocuments` — отдельный реестр строк накладных МК только в `/audit`;
- `controls.taxPools` — исходные суммы налоговых пулов;
- `warnings` — неподтверждённые правила и технические оговорки;
- `complete` — точный артикул МК найден, в его источнике нет отрицательных сумм
  или дублей, нет неизвестных платёжных документов и критичных проблем складской
  оценки.

Реестр ограничен 500 строками по умолчанию. Если он усечён, `controls.auditTruncated=true`; лимит задаётся `LAVKA_FOLIO_PROFIT_REPORT_MAX_AUDIT_DOCUMENTS`.

## Совместимость и безопасность

- запросы совместимы с SQL Server 2000 и jTDS 1.3.1;
- денежные расчёты в Java выполняются через `BigDecimal`;
- используется `mssqlTransactionManager` с `readOnly=true`;
- SQL содержит только `SELECT` и `NOLOCK`, чтобы отчёт не останавливал кассовую работу;
- `NOLOCK` означает, что во время одновременного проведения документа результат может кратковременно измениться; для окончательного месячного снимка отчёт лучше запускать после закрытия операций.

## Что ещё требует подтверждения владельца отчёта

1. Нужно ли менять серверное значение дополнительных работ Одессы `5000.00`;
   настройка: `LAVKA_FOLIO_PROFIT_REPORT_ODESA_ADDITIONAL_SALARY`.
2. Назначение небольших документов с кодами, которых нет в утверждённых правилах
   (например, найденный при июльской сверке код `КНИ`). Они намеренно остаются в
   `UNCLASSIFIED`.
