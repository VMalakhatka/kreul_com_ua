# Полная синхронизация: единица измерения Woo

Изменение 2026-09-19. Только Java `SyncServiceImpl`: существующие
`POST /sync/run` и `POST /admin/sync/products/force-refresh`.
Новые endpoint, массовый backfill и изменения WordPress не добавлены.

## Запись

Для непустого `CardTovExportOutDto.edinIzmer()` в штатный payload карточки
добавляется глобальный атрибут Woo `pa_edin_izmer` (`edin_izmer`). Значение —
только прежний `trim`, без перевода мл в граммы, замены запятой или сжатия
внутренних пробелов. Совместимое meta `_edin_izmer` остаётся как прежде.
Примеры: `250мл`, `125мл`, `2,5г`, `2  x  125мл`.

ID определяется в **целевом** Woo через `GET /products/attributes`, по точному
slug, один раз на запуск. Глобальный атрибут должен уже существовать. При его
отсутствии запуск явно завершается `WOO_UNIT_ATTRIBUTE_MISSING`; атрибуты с иным
slug не создаются. Это предварительное условие проверяется и для dry-run.

Woo REST v3 заменяет всю коллекцию `attributes`. Поэтому Java сначала читает
текущие атрибуты товаров окна через `GET /products?include=...` пакетами до 100 ID,
потом заменяет только `options` целевого атрибута. Остальные атрибуты, их options,
position, visible, variation и порядок сохраняются. Новый атрибут добавляется
после имеющихся, `visible=true`, `variation=false`. У существующего целевого
атрибута его flags/position не меняются. Пустой источник не отправляет attributes
или `_edin_izmer` и ничего не удаляет.

Термины назначаются штатным Woo REST посредством `attributes: [{id,options}]`.
Установленный Woo `WC_Product_Attribute::get_terms()` ищет термин по имени перед
созданием; отдельный Java POST создания терминов не добавлен. Повторное назначение
не добавляет вторую запись атрибута. При неполном/невалидном чтении коллекции
Java останавливается, не подменяя неизвестные атрибуты пустым списком.

## Товар с неизменённым hash

Обычный `/sync/run` сохраняет прежний diff и формат `_ms_hash`.
Для SKU текущего окна, отсутствующих в штатных update/delete, дополнительно
проверяется отсутствие/пустота `pa_edin_izmer`. Только для них читается единица
из ФОЛИО пакетным SELECT, без маппинга/создания категорий.

Если источник непустой, отправляется узкий update:

```json
{
  "id": 100,
  "attributes": ["полная сохранённая коллекция плюс/с изменённой единицей"],
  "meta_data": [{"key": "_edin_izmer", "value": "250мл"}]
}
```

Это схематическое представление: элементы attributes — объекты Woo, не строки.
В таком дозаполнении нет `_ms_hash`, цены, остатка, категории, имени, видимости,
описания, изображения, веса, габаритов и других meta. Уже непустое значение
у hash-unchanged товара не корректируется; повторный проход его пропускает.
Явный force-refresh по-прежнему обрабатывает полные карточки согласно своему
прежнему назначению. Только к этому штатному payload добавлена единица.

## Проверки и ограничения

Unit/mock-тесты покрывают новые/существующие карточки, сохранение остальных
полей/атрибутов, замену единицы, unit-only для unchanged, пустой источник,
повторный проход, dry-run, отсутствующий глобальный атрибут, неполное чтение
Woo и пакетное чтение 101 товара двумя GET.
Тесты не записывают данные production и не запускают фактический full sync.

Общие расписания, lock и retry/bisect остаются прежними. REST read/merge/write
не атомарен с ручным редактированием Woo: во время полной синхронизации не следует
параллельно менять атрибуты тех же товаров. Новая схема блокировок не вводилась.
Другие синхронизации, source SQL, цены, остатки и формат хеша не изменены.
