# Задание для фронта: отчёт «Прибыль Лавка»

## Цель

Сделать внутренний административный экран месячной прибыли Киева и Одессы по данным ФОЛИО. Экран должен показывать итог, структуру расходов, контрольные суммы и документы, которые требуют проверки.

Фронтенд не пересчитывает прибыль самостоятельно: все денежные результаты и правила приходят от backend. Это важно из-за округления старых `FLOAT` ФОЛИО и распределения налогов.

## API

### Дополнение 2026-09-08: детализация и периоды

После деплоя Java с `ruleVersion=2026-09-08.1` использовать новый раздел
[API: детальные строки и аудит](FOLIO_PROFIT_REPORT_API.md#детальные-строки-и-аудит-версия-2026-09-081).
Канонические поля и все 32 `lineId` перечислены там; не копировать классификатор
в PHP/JS. Денежные/decimal значения результата теперь JSON-строки.

1. В summary и audit показывать `expenseLines`, включая нулевые и ручные
   строки. `expenses` остаётся старым агрегированным представлением.
2. Добавить `kyivAdditionalSalary` ≥0, отсутствие → default0; Одесса default5000.
   Отправлять в обоих запросах одинаковые параметры. Не превращать default
   прошлого расчёта в override нового месяца; явный0 всегда сохранять.
3. Показывать `filters` как фактические условия; контрольный `operationTypes`
   не объявлять обязательным, когда `operationRequired=false`.
4. `periodDiagnostics[]` содержит вложенный `document` (полный DocumentLine),
   `status`, `reason`, `includedInTotals`, `amountTreatment`. Проблемные строки
   не дублируются в `documents`. Для смешанных405 итог остаётся предварительным:
   не распределять 55/350 и не заменять его нулём на фронте.
5. При `complete=false` явно помечать итог как требующий проверки. Показывать
   `controls.provisionalDocumentAmount` и `provisionalOperatingExpenseTotal`,
   а также `periodProblemCount`; это части уже показанного итога, не добавки.
6. Выводить отдельно `periodDiagnosticsTruncated`, `controls.auditTruncated`,
   `masterClass.auditTruncated`. Не называть ограниченную выгрузку полной.
7. Детализация строки связана через `expenseLineIds`; основной идентификатор
   налогового документа `SHARED_TAX_*` не является строкой конкретного города.
   Городские распределения брать из Java, не делить пул заново.
8. В аудите выводить безопасные `sourceInfo`, `periodNote`, `periodStatus`,
   `resolvedMonth`/`periodSource`, ставки и allocations. `paymentId` не заменять
   номером документа. МК остаётся в отдельном `masterClassDocuments`.

SQL/миграции ФОЛИО для этой доработки не нужны. Production и WordPress этим
изменением Java не обновлялись; повторную сверку API выполнять после деплоя.

### Существующие endpoints

- краткий отчёт: `GET /admin/folio/profit-report?month=YYYY-MM`;
- отчёт с реестром: `GET /admin/folio/profit-report/audit?month=YYYY-MM`;
- полное описание: [FOLIO_PROFIT_REPORT_API.md](FOLIO_PROFIT_REPORT_API.md).

Опциональные query-параметры:

| Поле | Тип | Назначение |
|---|---|---|
| `odesaTaxShare` | decimal 0…1 | Доля общего налогового пула Одессы |
| `rubToUahRate` | decimal > 0 | Курс RUB→UAH для зарплаты Донецка |
| `odesaMasterClassIncome` | deprecated | Не отправлять: backend игнорирует старое ручное значение |
| `odesaMasterClassReturn` | deprecated | Не отправлять: backend игнорирует старое ручное значение |
| `odesaAdditionalSalary` | money ≥ 0 | Необязательное переопределение серверных `5000.00`; явный `0` допустим |
| `kyivAdditionalSalary` | money ≥ 0 | Дополнительные работы Киева, default `0.00`; источник значения в inputs |
| `kyivStockWarehouseIds` | integer[] | Склады, участвующие в остатках Киева; default `1,7,12` |
| `odesaStockWarehouseIds` | integer[] | Склады, участвующие в остатках Одессы; default `5` |

Для дополнительной зарплаты ноль и отсутствие параметра имеют разный смысл:
`0` — явное переопределение, отсутствие — применить серверные `5000.00`.

## Экран

Предлагаемый маршрут: `/admin/reports/profit`.

### Верхняя панель

1. Выбор месяца. По умолчанию — предыдущий календарный месяц.
2. Кнопка `Рассчитать`.
3. Индикатор:
   - `Отчёт полный`, когда `complete=true`;
   - `Требует проверки`, когда `complete=false`.
4. Дата и время расчёта из `calculatedAt`.
5. Два обязательных для UI мультиселектора складов: `Остатки Киева` и `Остатки Одессы`.

Не отправлять запрос при некорректном формате месяца.

Справочник мультиселекторов загрузить через `GET /ref/warehouses`. Начальные значения — `1,7,12` для Киева и `5` для Одессы; после первого расчёта использовать фактически принятые значения из `inputs.kyivStockWarehouseIds` и `inputs.odesaStockWarehouseIds`. Нельзя оставить город без склада или выбрать один склад сразу для двух городов.

### Карточки городов

Для каждого элемента `cities` показать отдельную карточку:

- город (`KYIV` → `Киев`, `ODESA` → `Одесса`);
- валовая прибыль базы — `baseGrossProfit`;
- корректировка МК — `manualGrossAdjustments` (старое имя поля сохранено только
  для совместимости; это уже не ручная сумма);
- валовая прибыль после корректировок — `grossProfit`;
- операционные расходы — `operatingExpenses`;
- итоговая прибыль — `profit`.

Прибыль выделить основным числом. Отрицательную прибыль показывать красным, положительную — нейтральным/зелёным цветом согласно дизайн-системе.

### Остатки складов

Блок строится по `inventory`. Для каждого города показать:

- `Остаток на начало` — `openingAccountingValue`;
- `Остаток на конец` — `closingAccountingValue`;
- `Изменение остатка` — `accountingValueChange`;
- позиции на начало/конец;
- отрицательные позиции;
- ненулевые позиции с нулевой стоимостью.

Ниже раскрываемая детализация `warehouses` с названием и теми же суммами по каждому складу. Положительное изменение выделять как рост складского актива, отрицательное — как уменьшение. Не подписывать изменение как прибыль и не складывать его на фронте с итоговой прибылью.

### Мастер-класс Одессы

Удалить редактируемые поля дохода и возврата МК. Не отправлять
`odesaMasterClassIncome` и `odesaMasterClassReturn`, включая значения, которые
были автоматически заполнены старой версией страницы.

Показывать read-only карточку из `masterClass`:

- точный артикул месяца — `sku`;
- доход — `income` и `incomeLineCount`;
- возвраты — `returns` и `returnLineCount`;
- чистый вклад — `netContribution`;
- уже учтённая в базе валовая прибыль — `grossProfitAlreadyInBase`;
- фактически добавленная корректировка — `grossAdjustmentApplied`;
- проигнорированные/повторные строки — `ignoredLineCount` и
  `duplicateLineCount`;
- источник — `source`;
- усечение аудита — `auditTruncated`.

Если `articleFound=false`, показать ошибку, а не корректный ноль. Если артикул
найден и `income=0`, `returns=0`, это нормальный подтверждённый результат.

В `/audit` отдельно от кассовых/банковских `documents` показать таблицу
`masterClassDocuments`: дата и номер накладной, строка, SKU, типы документа и
движения, вид операции, признаки возврата/проведения, количество, цена, сумма,
`classification`, `includedInMasterClassContribution`, `reason`. Не смешивать её
с таблицей операционных расходов.

### Настраиваемые показатели

Сделать раскрываемый блок `Уточнения расчёта`:

- дополнительные работы/зарплата Одессы;
- доля налогов Одессы;
- курс RUB→UAH.

Значения по умолчанию для доли и курса брать из `inputs` первого ответа.
Для дополнительной зарплаты показывать фактически применённое
`inputs.odesaAdditionalSalary` и подпись по
`inputs.odesaAdditionalSalarySource`: `DEFAULT` → «серверное значение»,
`REQUEST_OVERRIDE` → «переопределено в запросе». Фронт не должен автоматически
превращать полученные `5000.00` в постоянный query-параметр при смене месяца:
передавать параметр только после явного изменения пользователем.

Под полем доли налогов показать пояснение: `Доля оформленных сотрудников Одессы`. Для текущего правила `0.4285714286` дополнительно показать `3 из 7 сотрудников`.

### Расходы

Таблица строится по `expenses`:

| Колонка | Поле API |
|---|---|
| Город | `city` |
| Статья | `label` |
| Документов | `documentCount` |
| Сумма | `amount` |
| Влияние на прибыль | `profitImpact` |
| Учёт | `accountingTreatment` |

Переключатели: `Все`, `Киев`, `Одесса`, `Не распределено`.

Человекочитаемые значения учёта:

- `OPERATING_EXPENSE` → `Вычтено из прибыли`;
- `CAPITALIZED_IN_INVENTORY` → `Включено в стоимость товара`;
- `EXCLUDED` → `Не является расходом отчёта`;
- `UNCLASSIFIED` → `Нужно определить правило`.

Строку импортного транспорта показывать даже при `profitImpact=0` и снабдить подсказкой: сумма уже отражается в учётной стоимости товара.

### Предупреждения

Блок строится по `warnings`, а не по текстам, зашитым во фронт.

Приоритет отображения:

1. `UNCLASSIFIED_DOCUMENTS`, `UNKNOWN_TAX_POOL`, `AMBIGUOUS_EXPLICIT_PERIOD`, `NEGATIVE_CLOSING_INVENTORY`, `ZERO_VALUE_CLOSING_INVENTORY` — ошибка/требует действий;
2. `MASTER_CLASS_ARTICLE_NOT_FOUND`, `MASTER_CLASS_DUPLICATE_MOVEMENT_ROWS`,
   `MASTER_CLASS_NEGATIVE_SOURCE_AMOUNT`, `MASTER_CLASS_LINES_IGNORED` — проверка МК;
3. `MASTER_CLASS_LEGACY_PARAMETERS_IGNORED` — старый фронт всё ещё отправляет
   удалённые параметры;
4. `IMPORT_TRANSPORT_CAPITALIZED`, `INVENTORY_CHANGE_INFORMATIONAL`, `LEGACY_FLOAT_ROUNDING`, `NOLOCK_READ` — информационное пояснение.

Текст брать из `message`. `details` использовать для суммы, количества или номера документа, если поле присутствует. Не считать список кодов закрытым: неизвестное предупреждение тоже должно отображаться.

### Контрольные суммы

В раскрываемом блоке `Контроль` показать значения из `controls`:

- выбранных документов и их сумму;
- операционные расходы;
- капитализированные затраты;
- исключённые документы;
- неклассифицированные документы и сумму;
- налоговые пулы.

Если `auditTruncated=true`, показать сообщение, что реестр ограничен сервером и отображает не все документы.

### Аудит документов

Кнопка `Показать документы` загружает `/audit` с теми же параметрами. До нажатия не загружать полный реестр.

Таблица `documents`:

- дата и номер;
- `BANK` → `Банк`, `CASH` → `Касса`;
- склад;
- назначение, код расхода, название и класс документа;
- исходная сумма и валюта;
- сумма отчёта в UAH;
- город и статья;
- способ учёта;
- включён ли документ в прибыль;
- пояснение `reason`.

Добавить фильтры по городу, статье, способу учёта и только неклассифицированным документам. Для таблицы допустим клиентский CSV-экспорт уже загруженных строк; он должен учитывать `auditTruncated` и не называться полным экспортом, если реестр усечён.

Служебного примечания ФОЛИО в ответе нет и фронт не должен пытаться его получать или показывать.

## Форматирование

- денежные значения: `Intl.NumberFormat('uk-UA', { style: 'currency', currency: 'UAH' })`;
- исходные RUB в аудите форматировать как RUB;
- не переводить денежные строки API через вычисления `Number`;
- долю показывать пользователю в процентах, но отправлять десятичной дробью;
- даты документов — `dd.MM.yyyy`, время расчёта — в часовом поясе пользователя с указанием даты.

## Состояния и ошибки

- отдельные состояния: начальная загрузка, пересчёт, загрузка аудита, пустой месяц, ошибка;
- предыдущий успешный результат можно оставить на экране во время пересчёта, но отметить как устаревший;
- HTTP 400 показать рядом с соответствующим полем, используя `error.code`/`error.message` ответа;
- HTTP 5xx или недоступность ФОЛИО показать общей ошибкой с кнопкой повторения;
- финансовые ответы не сохранять в `localStorage`; не включать параметры и тело ответа в клиентские аналитические события.

## Критерии приёмки

1. Пользователь выбирает месяц и склады каждого города, затем получает две карточки городов, остатки и таблицу расходов.
2. При незаполненных МК/дополнительной зарплате виден статус `Требует проверки` и соответствующие предупреждения.
3. Ввод нуля считается подтверждённым нулём и отправляется в API.
4. Изменение ручного значения вызывает новый backend-расчёт; фронт сам прибыль не пересчитывает.
5. Импортный транспорт виден как отдельная сумма с нулевым повторным влиянием.
6. Неклассифицированные документы заметны и доступны через фильтр аудита.
7. Основной экран не загружает `documents`; аудит загружается отдельно по действию пользователя.
8. Суммы не получают ошибок двоичной арифметики и отображаются с двумя копейками.
9. Для контрольного июля до ручных корректировок отображаются `264 551,50 грн` валовой прибыли Киева и `98 577,61 грн` Одессы.
10. Экран доступен только в защищённом административном контуре.
11. Один склад нельзя выбрать одновременно для Киева и Одессы; пустой список города не отправляется.
12. Изменение склада отображается отдельно и не прибавляется к прибыли на клиенте.
13. Доход и возврат МК нельзя редактировать; они получаются из `masterClass`.
14. `/audit` показывает отдельный реестр `masterClassDocuments`, включая
    проигнорированные строки и причину.
15. При смене месяца фронт не повторяет старые ручные суммы МК и не отправляет
    серверные `5000.00` как пользовательское переопределение без действия
    пользователя.

- изменение документов ФОЛИО;
- сохранение правил классификации из интерфейса;
- серверный Excel/CSV-экспорт;
- графики нескольких месяцев;
