# Задание для фронта: отчёт «Прибыль Лавка»

## Цель

Сделать внутренний административный экран месячной прибыли Киева и Одессы по данным ФОЛИО. Экран должен показывать итог, структуру расходов, контрольные суммы и документы, которые требуют проверки.

Фронтенд не пересчитывает прибыль самостоятельно: все денежные результаты и правила приходят от backend. Это важно из-за округления старых `FLOAT` ФОЛИО и распределения налогов.

## API

- краткий отчёт: `GET /admin/folio/profit-report?month=YYYY-MM`;
- отчёт с реестром: `GET /admin/folio/profit-report/audit?month=YYYY-MM`;
- полное описание: [FOLIO_PROFIT_REPORT_API.md](FOLIO_PROFIT_REPORT_API.md).

Опциональные query-параметры:

| Поле | Тип | Назначение |
|---|---|---|
| `odesaTaxShare` | decimal 0…1 | Доля общего налогового пула Одессы |
| `rubToUahRate` | decimal > 0 | Курс RUB→UAH для зарплаты Донецка |
| `odesaMasterClassIncome` | money ≥ 0 | Доход МК Одессы |
| `odesaMasterClassReturn` | money ≥ 0 | Возвраты МК Одессы |
| `odesaAdditionalSalary` | money ≥ 0 | Подтверждённые дополнительные работы Одессы |

Нулевое значение и незаполненное поле имеют разный смысл. Ноль означает, что пользователь проверил показатель и подтвердил отсутствие суммы; пустое поле означает, что показатель ещё не проверен.

## Экран

Предлагаемый маршрут: `/admin/reports/profit`.

### Верхняя панель

1. Выбор месяца. По умолчанию — предыдущий календарный месяц.
2. Кнопка `Рассчитать`.
3. Индикатор:
   - `Отчёт полный`, когда `complete=true`;
   - `Требует проверки`, когда `complete=false`.
4. Дата и время расчёта из `calculatedAt`.

Не отправлять запрос при некорректном формате месяца.

### Карточки городов

Для каждого элемента `cities` показать отдельную карточку:

- город (`KYIV` → `Киев`, `ODESA` → `Одесса`);
- валовая прибыль базы — `baseGrossProfit`;
- ручные корректировки — `manualGrossAdjustments`;
- валовая прибыль после корректировок — `grossProfit`;
- операционные расходы — `operatingExpenses`;
- итоговая прибыль — `profit`.

Прибыль выделить основным числом. Отрицательную прибыль показывать красным, положительную — нейтральным/зелёным цветом согласно дизайн-системе.

### Ручные показатели

Сделать раскрываемый блок `Уточнения расчёта`:

- доход МК Одессы;
- возвраты МК Одессы;
- дополнительные работы/зарплата Одессы;
- доля налогов Одессы;
- курс RUB→UAH.

Значения по умолчанию для доли и курса брать из `inputs` первого ответа. Не подставлять ноль автоматически в три ручных денежных поля. После изменения пользователь нажимает `Пересчитать`, и фронт повторяет запрос с заполненными параметрами.

Под полем доли налогов показать пояснение: `Доля оформленных сотрудников Одессы`. Для текущего правила `0.4285714286` дополнительно показать `3 из 7 сотрудников`.

### Расходы

Таблица строится по `expenses`:

| Колонка | Поле API |
|---|---|
| Город | `city` |
| Статья | `label` |
| Документов | `documentCount` |
| Сумма | `amount` |
| Влияние на прибыль | `profitImpact` |
| Учёт | `accountingTreatment` |

Переключатели: `Все`, `Киев`, `Одесса`, `Не распределено`.

Человекочитаемые значения учёта:

- `OPERATING_EXPENSE` → `Вычтено из прибыли`;
- `CAPITALIZED_IN_INVENTORY` → `Включено в стоимость товара`;
- `EXCLUDED` → `Не является расходом отчёта`;
- `UNCLASSIFIED` → `Нужно определить правило`.

Строку импортного транспорта показывать даже при `profitImpact=0` и снабдить подсказкой: сумма уже отражается в учётной стоимости товара.

### Предупреждения

Блок строится по `warnings`, а не по текстам, зашитым во фронт.

Приоритет отображения:

1. `UNCLASSIFIED_DOCUMENTS`, `UNKNOWN_TAX_POOL`, `AMBIGUOUS_EXPLICIT_PERIOD` — ошибка/требует действий;
2. `MASTER_CLASS_MANUAL_INPUT_REQUIRED`, `ODESA_ADDITIONAL_WORKS_UNCONFIRMED` — требуется ввод пользователя;
3. `IMPORT_TRANSPORT_CAPITALIZED`, `LEGACY_FLOAT_ROUNDING`, `NOLOCK_READ` — информационное пояснение.

Текст брать из `message`. `details` использовать для суммы, количества или номера документа, если поле присутствует. Не считать список кодов закрытым: неизвестное предупреждение тоже должно отображаться.

### Контрольные суммы

В раскрываемом блоке `Контроль` показать значения из `controls`:

- выбранных документов и их сумму;
- операционные расходы;
- капитализированные затраты;
- исключённые документы;
- неклассифицированные документы и сумму;
- налоговые пулы.

Если `auditTruncated=true`, показать сообщение, что реестр ограничен сервером и отображает не все документы.

### Аудит документов

Кнопка `Показать документы` загружает `/audit` с теми же параметрами. До нажатия не загружать полный реестр.

Таблица `documents`:

- дата и номер;
- `BANK` → `Банк`, `CASH` → `Касса`;
- склад;
- назначение, код расхода, название и класс документа;
- исходная сумма и валюта;
- сумма отчёта в UAH;
- город и статья;
- способ учёта;
- включён ли документ в прибыль;
- пояснение `reason`.

Добавить фильтры по городу, статье, способу учёта и только неклассифицированным документам. Для таблицы допустим клиентский CSV-экспорт уже загруженных строк; он должен учитывать `auditTruncated` и не называться полным экспортом, если реестр усечён.

Служебного примечания ФОЛИО в ответе нет и фронт не должен пытаться его получать или показывать.

## Форматирование

- денежные значения: `Intl.NumberFormat('uk-UA', { style: 'currency', currency: 'UAH' })`;
- исходные RUB в аудите форматировать как RUB;
- не переводить денежные строки API через вычисления `Number`;
- долю показывать пользователю в процентах, но отправлять десятичной дробью;
- даты документов — `dd.MM.yyyy`, время расчёта — в часовом поясе пользователя с указанием даты.

## Состояния и ошибки

- отдельные состояния: начальная загрузка, пересчёт, загрузка аудита, пустой месяц, ошибка;
- предыдущий успешный результат можно оставить на экране во время пересчёта, но отметить как устаревший;
- HTTP 400 показать рядом с соответствующим полем, используя `error.code`/`error.message` ответа;
- HTTP 5xx или недоступность ФОЛИО показать общей ошибкой с кнопкой повторения;
- финансовые ответы не сохранять в `localStorage`; не включать параметры и тело ответа в клиентские аналитические события.

## Критерии приёмки

1. Пользователь выбирает месяц и получает две карточки городов и таблицу расходов.
2. При незаполненных МК/дополнительной зарплате виден статус `Требует проверки` и соответствующие предупреждения.
3. Ввод нуля считается подтверждённым нулём и отправляется в API.
4. Изменение ручного значения вызывает новый backend-расчёт; фронт сам прибыль не пересчитывает.
5. Импортный транспорт виден как отдельная сумма с нулевым повторным влиянием.
6. Неклассифицированные документы заметны и доступны через фильтр аудита.
7. Основной экран не загружает `documents`; аудит загружается отдельно по действию пользователя.
8. Суммы не получают ошибок двоичной арифметики и отображаются с двумя копейками.
9. Для контрольного июля до ручных корректировок отображаются `264 551,50 грн` валовой прибыли Киева и `98 577,61 грн` Одессы.
10. Экран доступен только в защищённом административном контуре.

## Не входит в первую версию

- изменение документов ФОЛИО;
- сохранение правил классификации из интерфейса;
- автоматическое получение МК;
- серверный Excel/CSV-экспорт;
- графики нескольких месяцев;
- отдельный расчёт изменения стоимости непроданного складского остатка.
