# Выбранные расходные операции в прогнозе закупки

Проверено: 2026-09-28. Владелец — `FolioProductAnalyticsDao`.
Статус: реализовано и проверено на изолированной MariaDB; требуется деплой Java.

## Контракт

При `movementFilters.operationKinds.mode=INCLUDE` явно выбранные `РАСХОДНИКИ`
и `МУЛЬТИСБОРКА` дополняют спрос для закупки. Дополнение применяется только
к учётному расходному движению: `document_type=Р`, `affects_stock=1`,
`stock_direction=OUT`, `demand_mode<>ONE_OFF_ORDER`. Счета, поступления,
внутренние перемещения и разовые продажи не становятся спросом из-за этого правила.
Без INCLUDE этих операций (включая ANY/EXCLUDE) поведение остаётся прежним.

`regularSoldUnits` в ответе analytics query — историческое имя количественной
метрики, которую использует purchase preview. При явном выборе перечисленных
операций она содержит регулярные продажи плюс выбранный расход. Тот же предикат
применяется к `stockoutDemand.salesOnAvailableDays`: числитель поправки на отсутствие
и фактический спрос должны учитывать одинаковые операции. Отбор периода, склада,
stock-only, сегмента и остальные movement filters сохраняются.

Классификация исходных facts, `soldUnits`, `salesRevenue`, `salesCogs`,
`regularRevenue`, `regularCogs` и финансовая прибыль не меняются. Добавление расхода
в потребность не означает переклассификацию его в финансовую продажу.
Схема снимка остаётся прежней; достаточно нового query/preview после деплоя.

## Настройка сценария по отборам ФОЛИО

Для согласованного пользователем отбора:

- documentTypes INCLUDE `Р`;
- operationKinds INCLUDE `*РОЗНИЦА`, `МУЛЬТИСБОРКА`, `РАСХОДНИКИ`,
  `*ПРЕДОПЛАТА`, `*ПРЕДОПЛАТ`;
- demandModes ANY. Явный REGULAR-only по-прежнему исключает расходники,
  классифицированные NOT_APPLICABLE; запрос не отменяет другие фильтры молча.

Оба вида предоплаты — отдельные точные значения справочника. Они включаются
по отдельности; отсутствие последней буквы не является автоматически исправляемой
опечаткой. Нельзя выводить новый состав отбора только из старого скриншота.

После обновления сценария сохранить его ревизию и запустить новый preview.
Ранее созданные Excel/preview не пересчитываются автоматически. Откат — предыдущая
Java и предыдущая ревизия профиля; исходные facts не изменялись.

## Проверки

`FolioSelectedOperationDemandMariaDbTest` на disposable loopback MariaDB
проверяет добавление расходников/мультисборки, оба вида предоплаты, единый числитель
для дней наличия, неизменность финансовых показателей, ANY/EXCLUDE,
REGULAR-only, stock-only и исключение счетов, прихода, неучётных и разовых операций.
Также выполнены `FolioProductAnalyticsServiceTest` и `FolioStockoutDemandTest`.
Контроль отчёта: предоставленная карточка за нужные восемь месяцев даёт 108 единиц,
включая 19 расходников и 4 единицы короткого вида предоплаты вместо прежних 85.
