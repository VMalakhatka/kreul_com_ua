# Сравнение процедур учётных цен Paint_Rus и Paint_Ua

Дата: 2026-08-18.

Цель — перед подготовкой безопасных `LAVKA_*` procedures для рабочей базы
проверить, соответствует ли лабораторная исходная версия штатным
`I_UCHET_1_TOVAR` и `I_UCHET_TOVAR` в снимке `Paint_Ua` от 2026-08-11.

`Paint_Ua` не подключалась и не изменялась. Сравнение выполнено между:

- живыми определениями двух штатных procedures в изолированной `Paint_Rus`;
- локальной закрытой выгрузкой `dbo.syscomments` из `Paint_Ua`.

## Безопасный способ чтения

Произвольный SQL лаборатории по-прежнему запрещает экспорт `syscomments` как
`SOURCE_CODE_EXPORT`. Для проверки добавлен отдельный защищённый маршрут:

```text
GET /api/v1/procedure-fingerprints/accounting-prices
```

Он имеет фиксированный allowlist только из двух имён, использует общий lock
лаборатории и возвращает:

- количество и размер `syscomments` fragments;
- SHA-256 текста после нормализации переводов строк;
- SHA-256 после дополнительного удаления пробельных символов и приведения
  регистра.
- SQL-aware semantic SHA-256: комментарии и внешнее форматирование удаляются,
  но содержимое строковых литералов и quoted identifiers сохраняется.

SQL-текст, литералы procedures и произвольные имена объектов наружу не
передаются и в лог не записываются.

## Результат

Для `I_UCHET_1_TOVAR`:

- `Paint_Rus`: 5 исходных fragments, 17 128 символов;
- компактный SHA-256 обеих баз:
  `c6e88d92a941efac1029ee6507dfa44a065ed5ed1f2c11ab5c5eda37a290cd73`;
- semantic SHA-256 обеих баз:
  `3c9c57b2d4c9b08b3f9d9a0704f694f882b9649ef35ff77e93230de1f6296c00`;
- compact и semantic SHA совпали отдельно для каждого из пяти fragments.

Для `I_UCHET_TOVAR`:

- `Paint_Rus`: 5 исходных fragments, 16 316 символов;
- компактный SHA-256 обеих баз:
  `83d4d238736362b086ea6367fda6a4e18f210a28ec9f7bb01db28bd865b9ab3e`;
- semantic SHA-256 обеих баз:
  `b615580046285d006b3d909c1e12f858e88b41c2c7f810348eaaca6f8b56fb8c`;
- compact и semantic SHA совпали отдельно для каждого из пяти fragments.

Raw-нормализованные hashes части fragments отличаются только пробельными
символами. Причина — текстовый формат `.rpt`: он дополняет промежуточные части
до ширины колонки и теряет отдельные граничные пробелы. После удаления только
пробельных символов совпали целые procedures и каждый исходный fragment.
SQL-aware отпечаток дополнительно исключает ложное совпадение из-за возможного
различия пробелов внутри строковых литералов.

## Вывод

Штатные определения двух процедур в `Paint_Rus` и снимке `Paint_Ua` имеют
одинаковую исполняемую структуру и текст, если не учитывать форматирование.
Различий в операторах, именах, числах и строковых константах не найдено.

Поэтому лабораторная `LAVKA_I_UCHET_1_TOVAR_SAFE`, созданная из этой штатной
версии и прошедшая Paint_Rus golden-master, может служить основой отдельного
install script для `Paint_Ua`. Это ещё не разрешение устанавливать её в
рабочую базу: следующий gate — подготовить Paint_Ua-only DDL, проверить его
отпечаток и выполнить первый production rollback-preview в согласованное окно
без работы операторов ФОЛИО.

## Дополнительное исправление лаборатории

Во время полной сборки обнаружена гонка статуса safe-preview: терминальный
`running=false` мог стать видимым на несколько миллисекунд раньше освобождения
общего lock. Публикация терминального статуса перенесена после `release()`.
Полный набор лаборатории: 167 тестов, 0 failures.
