## Базовая платформа

Read-only снимок Paint_Ua от 2026-08-11 подтверждает Microsoft SQL Server `8.00.760` Service Pack 3, compatibility level `80`. Это действительно SQL Server 2000, а не только предположение по старому драйверу. Точное доказательство относится к этой инсталляции и дате; при работе с другой базой или после миграции перечитай `@@VERSION` и `sysdatabases.cmptlevel`.

Проект использует `net.sourceforge.jtds:jtds:1.3.1` и `net.sourceforge.jtds.jdbc.Driver`; в поставленном changelog jTDS есть отдельные исправления SQL Server 2000. Это осознанная граница совместимости, а не случайно забытая зависимость.

Не обновляй драйвер или SQL-диалект как побочное улучшение. Сначала создай отдельный тест подключения, кодировки, generated keys, транзакций и всех критичных запросов на копии базы.

У jTDS параметр `TDS=8.0` является legacy-обозначением протокола для SQL Server 2000. Не путай его с современным маркетинговым названием TDS 8.0/strict encryption в Microsoft Driver: это разные контексты. Не меняй параметры `TDS`, `charset`, `ssl` или Unicode вслепую — сначала зафиксируй текущий handshake и поведение на стенде.

## T-SQL для SQL Server 2000

Применяй только подтверждённый старый синтаксис.

| Задача | Совместимый подход | Не применять без доказательства |
|---|---|---|
| ограничение строк | `SELECT TOP n ...` | `OFFSET ... FETCH` |
| пагинация | стабильный `ORDER BY` + bounded `TOP` + исключение уже выбранных ключей | `ROW_NUMBER()` и оконные функции |
| генерация ключа | `IDENTITY`, JDBC generated keys, затем `@@IDENTITY` на том же соединении | sequence objects |
| значения NULL | `ISNULL(value, fallback)` | современные функции только ради удобства |
| обработка ошибки | транзакция Spring/Java с откатом | T-SQL `TRY...CATCH` |
| upsert | явные `SELECT`/`UPDATE`/`INSERT` под нужной блокировкой | `MERGE` |

Для пагинации партнёров используй установленный проектом порядок `_PARTNER.N_USER`, затем `ISNULL(NAME_USER,'')`, затем `ISNULL(NAMEP_USER,'')`. Порядок должен быть полным и стабильным; один `TOP` без стабильного порядка не является страницей.

Не считай новую функцию допустимой потому, что современный IDE её подсвечивает. Проверяй документацию именно версии сервера или выполняй безвредный пробный `SELECT`.

Ориентир по версии, который всё равно надо подтвердить на сервере:

| Версия | Пагинация |
|---|---|
| SQL Server 2000 | `TOP` + совместимое исключение либо keyset/cursor; без оконных функций |
| SQL Server 2005/2008 | доступен `ROW_NUMBER()`, но нет `OFFSET/FETCH` |
| SQL Server 2012+ | доступен `OFFSET/FETCH`; это ещё не доказывает, что он быстрее |

Смена jTDS затрагивает весь `folioDataSource` — счета, остатки, партнёров, медиа и generated keys. Не включай её в оптимизацию одного endpoint; это отдельная миграция с параллельным тестовым профилем и быстрым откатом.

## Пагинация и измерение

Перед изменением партнёрского DAO:

1. подтверди живой схемой, что `_PARTNER.N_USER` действительно `NOT NULL` и уникален; `NOT IN` с `NULL` или неполным tie-breaker может пропускать строки;
2. зафиксируй семантику текущих `limit`, `offset`, `q`, `types`, `total` и стабильный порядок;
3. добавь тесты на одинаковые имена, пустые `NAME_USER`/`NAMEP_USER`, кириллицу, границы страниц, глубокий offset и параллельную вставку;
4. на разрешённой копии базы сравни планы, logical reads и время репрезентативных запросов, включая отдельный `COUNT`;
5. проверь, не доминируют ли `%q%`, `CAST` индексированного `varchar` или Unicode conversion — замена только offset-механизма может ничего не ускорить;
6. для глубоких страниц предпочитай новый cursor/keyset-контракт по уникальному ключу; старый offset сохраняй до согласованной миграции клиентов.

`total` и `items` выполняются разными запросами и при конкурентных изменениях могут описывать разные моменты. SQL Server 2000 не даёт современную snapshot isolation: либо документируй допустимую eventual consistency, либо проектируй короткую lock-based консистентность и измеряй блокировки. Не усиливай isolation без бизнес-требования.

## JDBC и соединение

В проекте два источника данных. Для ФОЛИО используй только квалификаторы:

- `folioDataSource`;
- `folioJdbcTemplate`;
- `folioNamedJdbc`;
- `mssqlTransactionManager`.

Не используй WordPress/MariaDB transaction manager для операций ФОЛИО и не рассчитывай на общую атомарность двух баз без явного протокола компенсации.

`SCOPE_IDENTITY()` в отдельном вызове `JdbcTemplate` однажды вернул `NULL`, потому что вызов оказался на другом соединении. Для `SCL_MOVE.RECNO` текущий безопасный паттерн:

1. создать `PreparedStatement` с запросом generated keys;
2. выполнить `INSERT`;
3. прочитать `getGeneratedKeys()`;
4. если драйвер не вернул ключ, выполнить `SELECT CAST(@@IDENTITY AS numeric(18,0))` через тот же объект `Connection` до его возврата в pool;
5. не выполнять между вставкой и чтением ключа посторонние вставки на этом соединении.

Не переносить fallback в отдельный `jdbc.queryForObject(...)`.

`spring.datasource.hikari.connection-init-sql=SET NAMES utf8mb4` относится к MySQL-семантике и не должно использоваться как решение кодировки MS SQL. Кроме того, программно созданный Hikari в `SpringConfig` может не наследовать произвольные Boot-настройки первичного datasource; проверяй фактическую конфигурацию bean.

У jTDS `loginTimeout` и `socketTimeout` могут по умолчанию быть нулевыми, то есть ожидание способно стать неограниченным. Hikari `connectionTimeout` ограничивает ожидание свободного соединения из pool, а не сетевое чтение JDBC. Настраивай и проверяй эти таймауты отдельно, не меняя production URL без теста длительных операций ФОЛИО.

Старый сервер/TLS и Java 17 могут не согласовать современные cipher/certificate requirements. Не включай `ssl=require`/`authenticate` на production вслепую. Сначала проверь копию/стенд; если современный TLS на сервере невозможен, выноси транспортную защиту в закрытую сеть, VPN или tunnel по решению владельца инфраструктуры.

## Кодировка и кириллица

Живой снимок подтверждает server/database collation `SQL_Ukrainian_CP1251_CI_AS` и code page `1251`. Все 312 символьных поля в 26 исследованных таблицах и все 588 строковых параметров procedures используют эту collation; Unicode-полей/параметров в выгрузке нет. Старые `varchar`/`char` и имена файлов должны быть совместимы с Windows-1251. Не заменяй автоматически `varchar` на Unicode-предположение и не пропускай проверку round trip.

Исследованная сессия имела `us_english` и `@@DATEFIRST = 7`. Это дополнительная причина передавать даты типизированными параметрами и не полагаться на русский/украинский строковый формат или первый день недели клиента.

jTDS обычно отправляет строковые параметры как Unicode. Для индексированного `varchar` на SQL Server 2000 это способно вызвать неявное преобразование и scan вместо seek. Не переключай `sendStringParametersAsUnicode=false` только ради скорости: сначала проверь CP1251 round trip, кириллицу, query plan и результаты точного поиска на копии базы.

Критичные символы:

- тип счёта — кириллическая `С` U+0421, не латинская `C` U+0043;
- типы расхода/прихода — кириллические `Р`/`П`, не латинские `P`;
- суффиксы счётчиков `СU` и `СN`: первая буква кириллическая, вторая латинская;
- `NSF_ORG.NAME_USER` имеет ведущий специальный пробельный байт `0xA0`, поэтому код сравнивается как `RIGHT(NAME_USER, 2)`.

В `.properties` записывай не-ASCII значения через `\uXXXX`. Сырые кириллические defaults уже приводили к mojibake вида `Ð...` из-за интерпретации ISO-8859-1.

Для filename перед записью используй `Charset.forName("windows-1251").newEncoder().canEncode(value)`. Проверяй длину в байтах/символах согласно реальному `varchar`, basename и точный регистр/символы.

## Числа и даты

- Деньги и количества держи в Java как `BigDecimal`; преобразуй к типу базы только на границе JDBC.
- `SCL_NAKL.N_PLAT_POR` — `float NOT NULL`, поэтому видимый номер должен быть числовым. Не передавай составной текстовый order id.
- `SCL_NAKL.UNICUM_NUM` — технический ключ, а не отображаемый номер.
- При записи документов нормализуй `SCL_NAKL.DATE_P_POR` и `SCL_MOVE.DATE_PREDM` на `00:00:00`: UI ФОЛИО с дневным фильтром не показывал строку с полуднем.
- При чтении диапазона используй полуинтервал `[dateFrom, nextDay)`, чтобы не потерять старые строки с ненулевым временем.
- Передавай даты через типизированный `PreparedStatement`/`Timestamp`, а не локализованную строку: старый клиент зависел от языка SQL Login и regional settings.
- `timestamp` в MS SQL этой эпохи — rowversion, не календарная дата.

## Параметры и пакетные запросы

SQL Server ограничивает один запрос примерно 2100 параметрами; в проекте это отражено настройкой `lavka.mssql-max-params=2100`. Оставляй запас для прочих параметров и дроби списки SKU/ID на чанки. Не собирай значения конкатенацией: параметризуй каждый чанк.

## Диагностика блокировок

Старый Query Analyzer или незавершённый `SELECT INTO` может держать блокировку и создавать впечатление, что Java/jTDS завис.

Безопасная последовательность:

1. открыть отдельное соединение вне заблокированной пользовательской транзакции;
2. выполнить `sp_who2`;
3. для подозрительного SPID выполнить `DBCC INPUTBUFFER(<spid>)`;
4. в исходном окне проверить `@@TRANCOUNT` и штатно `COMMIT`/`ROLLBACK`;
5. применять `KILL <spid>` только после точного определения владельца и влияния, с явным разрешением пользователя.

Не начинай с перезапуска Java или замены драйвера, пока не исключён серверный blocker.
