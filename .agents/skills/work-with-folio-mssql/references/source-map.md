## Правило выбора источника

Сначала ищи локальный ответ, затем при необходимости проверяй живую схему чтением. У каждого утверждения держи один из статусов:

| Статус | Значение |
|---|---|
| подтверждено живой базой | `sp_help`, метаданные, снимок строки или воспроизводимый эксперимент на текущей базе |
| подтверждено кодом | реализовано и используется текущим Java-модулем; ещё не доказывает неизменность схемы |
| документация | руководство производителя или проектная документация без живой проверки |
| гипотеза | вывод по имени, соседним полям или неполному наблюдению; нельзя использовать для записи |

При расхождении живой базы и руководства не «усредняй» сведения. Зафиксируй обе версии и используй живую схему для этой инсталляции.

## Каталог базы

`docs/00_DATABASE_CATALOG.md` — основной поисковый индекс примерно по 196 таблицам. В нём есть:

- происхождение знаний и уровни уверенности;
- карточки таблиц, ключи и связи;
- перечень полей из документации и наблюдений;
- зоны, которые ещё требуют проверки.

Ищи в нём точное имя таблицы и поля. Не читай весь файл, если нужна одна карточка. Скриншоты `docs/Снимок экрана 2026-06-30 ...png` подтверждают перечень таблиц, но почти не добавляют семантики полей.

| `docs/contentr.rpt` | начала определений и отдельные доступные фрагменты `dbo.syscomments` | каждая строка обрезана примерно до 255 символов; отсутствие текста ничего не доказывает |

Все семь triggers снимка принадлежат CRM-таблицам; triggers на основных `SCL_*`, `NSF_ORG`, `_PARTNER`, `ALL_ARTC` и `img_prod` не найдены. `card_tov_export` существует как view и используется текущим Java DAO.

`vpr.rpt`, `contentr.rpt`, семь структурных/агрегатных `.rpt` и исправленный `02_index_correct.rpt` прошли эвристическую проверку `check_no_secrets.py`. Это не делает их автоматически публичными: проверяй каждый изменённый файл повторно и не публикуй лишние operational counts.

Повторяемые read-only запросы находятся в `docs/folio-export/01_live_columns.sql`…`07_environment.sql`; полный текст модулей выгружает `docs/export_folio_definitions_full.sql`. Запускай каждый файл отдельно в нужной базе и сохраняй результат вне Git до проверки секретов. В `01/02` имя `_RECLAMA` уже исправлено после обнаруженной опечатки.

Для golden-master экспериментов на изолированной копии Paint_Rus используй только подготовленный комплект `docs/folio-experiments`. Raw `.rpt` этого комплекта игнорируются Git и не являются переносимым знанием.

Автоматизированная локальная лаборатория находится в `folio-rus-lab/`. Её CLI и контракт описаны в [lab-api.md](lab-api.md). Это исполняющий инструмент, а не источник бизнес-истины: доказательством становится только воспроизводимое before/after наблюдение, проверенное штатным UI или отчётом.

`docs/contentr_full.rpt` покрывает все 262 procedures/views/triggers, но проверку **не прошёл**: обе потенциальные строки с реквизитами подключения относятся к `dbo.B_VIEW_SCLAD_GRP1`. Не цитируй совпадения, не добавляй raw-файл в Skill/Git и не считай его пригодным к передаче. Проверенные обезличенные выводы уже перенесены в [core-procedure-behavior.md](core-procedure-behavior.md); процесс безопасного экспорта и очистки описан в `references/views-and-procedures.md`.

## Текущий Java-модуль

Главные точки входа:

- `src/main/java/org/example/proect/lavka/config/SpringConfig.java` — отдельные DataSource/JdbcTemplate/transaction manager для ФОЛИО и WordPress;
- `controller/Folio*Controller.java` — HTTP-контракты;
- `service/folio/FolioAccountService.java` и `FolioOrderAccountService.java` — транзакционная оркестрация;
- `service/folio/FolioNumberAllocator.java` — технический и видимый номера;
- `dao/folio/FolioAccountDao.java` — SQL счетов, остатков и idempotency;
- `dao/folio/FolioPartnerDao.java` — совместимый поиск и пагинация партнёров;
- `service/folio/FolioProductMediaService.java` и `dao/folio/FolioProductMediaDao.java` — main/gallery images и CP1251;
- `src/main/resources/application.properties` — имена переменных среды и legacy driver; не копируй значения по умолчанию с адресами или логинами;
- `pom.xml` и `jtds-1.3.1-dist/` — фактически используемый jTDS 1.3.1.

При конфликте комментария и SQL читай метод целиком, владельца транзакции и вызывающий сервис.

## Знания из проектного чата

Чат проекта, в котором разрабатывался Java-модуль, содержит результаты живых экспериментов. Существенные подтверждения уже перенесены в справочники этого Skill:

- SQL Server 2000 и осознанный выбор jTDS 1.3.1;
- generated key на том же соединении;
- живой `IDENTITY` у `SCL_MOVE.RECNO` вопреки старому описанию;
- штатная нумерация через `NSF_ORG.N_3` и суффиксы `СU`/`СN`;
- кириллические символы, CP1251, фактические длины полей;
- необходимость триады `SCL_NAKL` + `SCL_MOVE` + `SCL_ADDN`;
- влияние учитываемого счёта на `SCL_ARTC.REZ_KOLCH`;
- дата документа на полуночи для фильтра ФОЛИО;
- блокировки старого SQL Server и безопасность preview/idempotency.

Считай эти сведения доказательствами конкретной текущей инсталляции, а не универсальной гарантией для любой базы ФОЛИО. При переносе на другую базу перепроверь их.

## Чувствительные данные

Лист `Устройства` в старом XLS содержит инфраструктурные адреса и учётные данные. Он намеренно не включён в Skill. Не открывай и не цитируй его без отдельной необходимости, не добавляй его содержимое в код, логи, документацию или ответы. Для схемы используй только лист `Таблицы`.

Определения procedures/views также могут содержать hardcoded connection strings, сетевые пути или секреты. Сырую выгрузку держи вне репозитория, проверь `scripts/check_no_secrets.py`, вручную очисти чувствительные литералы и только затем добавляй полезную копию. Проверка выводит лишь тип находки и позицию, но не само значение.
